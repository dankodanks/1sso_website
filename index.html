The old way

            
25 lines of keyboard mash.

            

              You want to build a simple app, and suddenly you're managing a wall of
              gibberish in your .env. A dev console for login, another for each API,
              and a credentials file you can't safely share.
            

            
    
              
  • ✕ A dev console per service
    • 
              
  • ✕ Secrets copy-pasted into every project
    • 
              
  • ✕ Sharing a repo means sharing a credentials file
    • 
            

          


          

            
The 1SSO way

            
One key. Configure the project.

            

              Put one API key in the project .env. In the dashboard, enable the
              auth providers and API connectors approved for that project — including keys you
              bring yourself. Lovable, Bolt, Cursor, and MCP clients use that same key.
              Sharing the repo means sending one line, not a credentials file.
            

            
    
              
  • ✔ One key for the project
    • 
              
  • ✔ Providers and connectors set in the dashboard
    • 
              
  • ✔ Collaborators get one line, not a vault

// the toolbox

          
What the first release actually covers.

          
One project key for auth, approved API connectors, and AI/MCP workflows. You configure them. Managed databases and storage come later.

        


        

          

            
🔐

            
Single-key authentication

            
Sign-in goes through the providers you enable for the project. The app calls 1SSO with one key — you still choose and configure those providers in the dashboard.

          


          

            
🔌

            
Approved API routing

            
Calls go through connectors approved for the project. When a service needs your own credential — OpenAI, analytics, your Supabase project — you store that key in the dashboard, not in the repo.

          


          

            
✦

            
AI & MCP workflows

            
Lovable, Bolt, Cursor, and MCP clients use the same project key. They can call the auth and connectors you've already configured. They don't turn new services on by themselves.

          


          

            
🗄️

            
Managed database & storage (coming soon)

            
Tables, file storage, and background jobs are on the roadmap. The first release does not provision a database, buckets, or functions.
